# 顾问投入产出比模块 ExecPlan

## 目标

在“桉侨集团”范围新增“顾问投入产出比”模块，按月、按顾问汇总投入与预计营收，并保留工资表、营收明细表和各公司序时账的来源链路。

## 数据口径

- 基本工资、提成：来自集团范围当月已发布的“每月工资表”；仅部门名称含“顾问”的人员组成顾问主档，其他部门人员排除。
- 人员费用：来自当前员工有权查看的各公司当月已发布序时账；只取销售费用、管理费用中摘要或科目明确包含顾问姓名的非结转分录，排除工资、薪酬、提成，避免重复。
- 预计营收：来自集团当月已发布营收统计文件“总营收明细表”的“月份”“签约顾问/渠道”“预计营收”“业绩归属”列；只取所选期间并只归入工资顾问主档。
- 投入合计 = 基本工资 + 提成 + 人员费用；投入产出比 = 预计营收 / 投入合计。
- 缺失来源不补零、不复用其他期间；无法唯一匹配的姓名单列为待匹配。

## 实施步骤

1. 新增 `payroll_statement` 上传类型、工资表结构识别与原始行保存。
2. 扩展营收统计解析，保存“总营收明细表”顾问产出行。
3. 新增顾问姓名归一、序时账费用归集和集团分析接口。
4. 新增独立权限、集团导航模块、来源说明、汇总卡片、投入产出表和明细弹层。
5. 增加工资/营收/序时账组合回归，验证权限、空态、姓名匹配和重复费用排除。

- 已补充顾问/非顾问部门、跨月营收排除、营收名册外人员排除、来源版本变更及前端刷新机制回归。
- 已新增可点击的顾问平均投入产出比卡片：所有顾问平均值采用有投入顾问个人比率的算术平均；弹层按业绩归属展示各地区投入、预计营收和比率，跨地区顾问投入按预计营收占比分摊。

- 已发布的旧工资批次若缺少入职字段解析结果，会从保留的原始工资文件重新解析并按上传批次缓存，无需用户重新上传或重新发布。

## 交付结果

- 版本：`1.1.18`
- 分析接口：`GET /api/analysis/consultant-roi?company=group&period=YYYY-MM`
- 空缺来源不补零、不跨公司或跨期间复用；顾问工资名册中无营收的人员保留为“缺营收”，营收表中不属于顾问部门名册的人员不进入明细并计入来源核对数量。
- 真实文件验收：2026 年 6 月工资表识别 87 名有效人员，其中顾问部门 30 人、非顾问部门排除 57 人；顾问预计营收 `4,541,013.29` 元、投入 `488,312.08` 元、整体投入产出比 `9.2994`。
- 浏览器验收：隔离环境选择桉侨集团 / `2026-06` 后，五张指标卡保持单行；顾问平均投入产出比为 10.90 倍，弹层正确列出深圳 17.30 倍、广州 7.93 倍等地区比率。取消基本工资标签后平均值联动为 127.36 倍；旧工资批次自动重解析出当月新员工，点击杨雯棋姓名旁“新”标记显示入职时间 `2026-06-01`。
- 最终验证：`npm run check`、`node --check public/app.js`、`npm run check:deploy`、`git diff --check` 均通过，`npm test` 共 74 项全部通过。

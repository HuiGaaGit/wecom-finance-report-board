# 权限中心第一阶段重构 ExecPlan

## 目标

在不改变现有权限接口、数据库结构、角色默认值和最终生效权限的前提下，把不断增长的“完整权限树”重构为可扩展的权限中心。桌面端改为员工列表与编辑区两栏布局，手机端改为员工列表到员工详情的两级流程，避免模块继续增加后页面横向溢出和纵向无限增长。

## 交付范围

- 权限中心提供“员工授权、角色预设、授权审计、全局设置”四个顶层视图。
- 员工编辑器提供“快速配置、模块权限、高级设置”三个页签。
- 模块权限按财务报表、经营分析、报表上传、系统管理分类，并以紧凑矩阵展示浏览、导出、查看明细、导出明细等动作。
- 保留角色预设、个人追加/移除、公司范围、期间范围、明细偏好、复制员工权限和移除授权能力。
- 将常驻第三栏摘要改为按需打开的生效摘要抽屉，并增加未保存变更计数、取消和保存操作。
- 角色预设页只读展示现有预设及使用人数；授权审计页只展示当前接口能够可靠提供的信息或明确空态；全局设置承载员工水印开关。
- 不在本阶段新增 grants/denies 数据模型、角色模板编辑接口、批量授权接口或数据库迁移。

## 兼容约束

- 员工权限档案仍保存完整 `permissionKeys`，请求载荷和 API 路由保持不变。
- `selected` 与 `baseline` 集合继续作为界面和保存的事实源，完整保留“预设、已追加、已移除”语义。
- 关闭 `module.cash_analysis.view` 时继续移除 `module.cash_analysis.net_positions.view`；开启子权限时继续自动开启父权限。
- 不修改既有员工、角色、公司与期间范围，也不重写历史权限档案。
- 并发的顾问投入产出比修复预留 `1.1.15`；本任务在其稳定事实源上继续递增版本并保留相关改动。

## 实施步骤

1. 重新读取稳定源码与并发差异，固定权限目录、角色、员工档案和现有保存行为。
2. 拆分权限中心壳层、员工列表、员工编辑、快速配置、权限矩阵、高级设置、生效摘要和全局设置渲染逻辑。
3. 用分类矩阵替换全量展开树；增加搜索、已开启/个人调整/高风险筛选，以及分类与行级批量操作。
4. 增加本地草稿和脏状态管理，切换员工或取消时恢复服务端值，保存时沿用现有接口载荷。
5. 完成两栏桌面布局和手机列表/详情切换；桌面 1280px 不出现权限工作台横向滚动。
6. 增加静态与行为回归，覆盖矩阵动作映射、父子依赖、草稿保存、移动端视图和已有接口契约。
7. 更新 README、源码版本、UI 版本与发布说明；生成不覆盖旧产物的版本包。
8. 运行语法、测试、部署配置检查，并在 1280×720 与 390×844 浏览器中逐项验收。

## 验收标准

- 四个顶层视图与三个员工编辑页签均可操作，未实现的后端能力不伪装为可用功能。
- 现有员工保存前后的权限键、公司范围、期间范围和明细偏好按用户操作准确一致。
- 矩阵不为不支持的动作生成权限；角色预设与个人调整状态显示准确。
- 1280px 桌面端权限工作台无横向滚动，员工编辑区不再一次展开所有分类。
- 390px 手机端先显示员工列表，进入员工后只显示详情并可返回；底部保存栏可用。
- `node --check app.mjs`、`node --check public/app.js`、`npm run check`、`npm test`、`npm run check:deploy` 全部通过。

## 发布与回滚

- 本阶段没有数据库迁移，发布失败时可直接切回上一版本应用和静态资源。
- 保留上一版本发布包，不覆盖历史构建产物，不删除任何员工权限档案。
- 仅在阅读 `docs/PRODUCTION_OPERATIONS.md` 和当前生产部署 ExecPlan、确认新服务器链路后才允许部署；禁止使用旧 ECS 或旧 `/report` 地址。

# 离职日期同步与全站滚动层级

## 目标

修复顾问离职标签只有状态、没有日期的问题：财务专用企微同步器分别精确读取离职表 `B:B` 的离职日期和 `D:F` 的所属公司、姓名、英文名，按原始行号合并，绝不读取 `C:C` 离职原因。同时统一全站滚动容器、顶部栏、侧栏、模块工具栏和表头的 sticky 高度与层级，避免内容上滚侵入品牌区或被顶部栏裁切。

## 实施

1. 将企微区域结果保留请求范围中的原始行号，分别验证 B 列与 D:F 的起始列、最大宽度、返回行数和表头；按行号而非跨行姓名或英文名合并。
2. 兼容 WPS 日期文本及安全的日期序列值，统一输出 `YYYY-MM-DD`；脱敏快照升级并只允许 `name`、`englishName`、`companyName`、`employmentStatus`、`exitDate`，读取旧快照时保持兼容但触发一次升级刷新。
3. 离职标签只读取 `exitDate`；空日期显示“待补充”，在职人员不返回离职日期。普通员工可看标签日期，但不接收同步诊断字段。
4. 统一 CSS 变量 `--app-header-height` 和层级；全局 header 固定于视口顶端，侧栏从 header 下方开始，文档页面作为唯一纵向滚动区域。当前全站表头统一随表格自然滚动，避免任何表头悬浮进入 header；管理区确需 sticky 的局部面板从同一变量计算偏移。
5. 清理造成主内容侵入品牌区的负偏移、transform 或不可收缩宽度；全站表格只允许各自容器横向滚动。
6. 版本顺延至 `1.1.63`，补 README、部署说明、生产说明和候选包；保留 `1.1.62` 已部署的累计、模型映射及顾问口径。

## 验证

- 单元测试覆盖有日期、空日期、表头移动、B 与 D:F 非连续精确读取、按原始行号合并、拒绝越界、离职原因不进入命令/日志/快照、在职人员无离职日期。
- 服务端测试覆盖 schema/字段白名单、旧快照刷新、上传与手动刷新、普通员工无诊断字段。
- 浏览器覆盖管理员和普通员工；桌面 `1280/1440`、窄屏 `390×844`，从中段向顶部反复滚动、打开/关闭报销科目浮层和折叠模块，检查标题不裁切、无白块/抖动/横向位移、控制台无错误。
- 运行 `node --check app.mjs`、`node --check public/app.js`、`node --check deploy/sync-consultant-directory.mjs`、`npm test`、`npm run check:deploy`、`git diff --check`。

## 部署与回滚

- 生产发布前固定候选包并完成服务器 Docker 全测与 SQLite 一致性备份。保留财务专用 CLI、独立 HOME/XDG_CONFIG_HOME、五个 systemd unit 和三个已启用监听。
- 切换容器前先用候选同步器纯 import，再手工同步一次；只确认脱敏样例日期不再为空，不在日志或报告中输出真实人员信息。文件继续为 `0600`、所有者 `20117:20117`。
- 任一范围、同步、测试、Nginx、运行隔离或页面验收失败立即恢复 `1.1.62` 源码、镜像和同步脚本；数据库完整时不得以旧备份覆盖业务数据。

# 报单表客户与项目匹配

## 目标

在上传报表页增加集团报单表入口，读取“报价单/报价表”工作表的“合同编号、客户姓名、项目”三列，并在主营业务分析中优先按合同编号补充、纠正客户名称和项目名称。

## 约束

- 报单表是集团级累计主数据，只作为主营业务分析的匹配来源，不作为普通财务报表导航或整表导出。
- 上传时不选择会计月份，报单表存入独立“全历史”数据域；保留发布历史，用户可见版本号取文件名末尾后缀，主营业务分析使用最新已发布版本。
- 合同编号采用规范化后的精确匹配；不进行客户名或项目名模糊匹配，避免串单。
- 保留现有序时账收入、成本和金额口径，只替换已命中合同的客户名称与项目名称。
- 原始报单表可能超过 20 MB，应用请求体上限需与生产 Nginx 上传上限协调。

## 实施步骤

1. 核对用户样本表的真实工作表、表头行和合同编号格式。
2. 新增 `quotation_ledger` 源数据类型、工作表解析和字段校验。
3. 在上传页增加专用入口、文件名自动识别及集团主数据提示。
4. 主营业务分析加载最新已发布报单表，以合同编号精确匹配客户和项目。
5. 增加接口、解析、权限及前端回归测试，递增版本号并更新说明。
6. 用用户样本完成本地上传、发布和页面验证。

## 验收标准

- 用户样本可成功上传并识别“报价单”中的三列，不受文件名中的历史年月误判影响。
- 用户样本无需提供归属月份，文件名 `202502年报价单台账汇总黎 -0903.xlsx` 识别为全历史数据、版本 `0903`。
- 截图中的合同编号在主营业务分析中显示台账客户和项目，例如 `20260709-1825` 显示“吴红翔 / 瓦努阿图-护照”。
- 未命中的合同继续使用原序时账识别结果并给出匹配统计，不影响金额。
- 报单表不可通过普通报表接口整表浏览或导出。
- `npm run check`、`npm test`、`npm run check:deploy` 通过，并完成浏览器窄屏/桌面基本验证。

# 管理员浏览日志模块 ExecPlan

## 目标

新增仅管理员可见的“浏览日志”模块，集中查询所有员工在财务看板内的页面浏览、数据访问和操作记录，并提供筛选、分页、详情查看与受控批量删除能力。

## 交付范围

- 复用并升级现有 `audit_logs`，保留全部历史操作记录，补充日志类型、模块、公司和期间结构化字段。
- 前端页面切换时记录一次页面浏览；现有报表读取、分析读取、上传、发布和权限修改等记录继续保留。
- 新增管理员专属日志查询接口，支持人员、浏览/操作类型、动作、模块、公司、期间、起止时间和关键词组合筛选。
- 新增分页列表、统计卡片、日志详情、全选/勾选及批量删除；删除日志的动作自身不可静默，必须生成新的操作日志。
- 普通员工不显示模块，直接调用管理接口返回 403。

## 实施步骤

1. 扩展日志表与索引，并为既有 `view_*` 记录补齐浏览类型。
2. 统一日志写入函数的结构化上下文，新增页面浏览采集接口。
3. 新增管理员查询和批量删除接口，完成参数校验、分页和权限保护。
4. 在侧栏和页面容器中加入“浏览日志”，实现筛选、详情和批量管理交互。
5. 补充接口权限、筛选、浏览采集、删除留痕和前端契约测试。
6. 递增到 `1.1.20`，同步源码、UI、说明与版本化发布包，运行项目最小验证。

## 验收标准

- 管理员能看到全部员工日志并按多个条件组合筛选；普通员工看不到入口且无法越权读取。
- 页面访问只在页面或查看范围实际变化时记录，不因同页自动刷新重复写入页面浏览事件。
- 浏览与操作日志清晰区分，历史日志不丢失。
- 批量删除仅作用于明确勾选的记录，并新增一条包含删除数量的管理员操作记录。
- `npm run check`、`npm test`、`npm run check:deploy` 和 `git diff --check` 全部通过。

## 发布与回滚

- 数据库升级只新增列和索引，不删除旧字段；旧版本仍可读取原有五列日志。
- 发布时保留上一版本产物。若界面或接口异常可回滚应用版本；新增日志列无需回退。
- 本任务只准备本地交付版本，未获得用户明确部署要求前不操作生产环境。

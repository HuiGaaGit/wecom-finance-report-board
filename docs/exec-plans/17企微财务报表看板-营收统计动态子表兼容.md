# 营收统计动态子表兼容

## 目标

营收统计表上传时先识别工作表内实际存在的连续表格区域，再依据区域标题、字段表头和数据边界生成当月及年度累计子表。上传期间由可靠的当月标题、字段月份和文件名共同判断，不再把累计年份或历史月份误作当前期间。另以动态解析后的“总营收明细表”为统一事实源，为各分公司提供按业绩归属隔离的营收趋势分析。

## 约束

- 不按固定行号、固定列号、固定 B1-B8/L1-L6 数量或固定业务名称强制识别。
- 子表仍必须具备可验证的标题、连续字段表头和非空数据区；相邻区域不能互相吞并。
- 文件包含多个历史月份时，以当月汇总区域的月份为当前期间，累计区只提供年份和历史明细，不参与月份冲突判定。
- 模型仅可辅助解释已脱敏的标题、字段和坐标，最终区域、字段与数据边界继续由程序复核；模型失败不得阻断规则已识别的上传。
- 已发布旧文件在保留原始文件时可按新解析器动态重解析，不要求重新上传。
- 分公司分析只接收本地区明细；管理员保存的数据标签组合为全局口径，普通员工只能查看。

## 实施步骤

1. 对用户提供目录中的多代营收统计文件建立工作表、标题、表头、有效区域和期间差异矩阵。
2. 把期间识别拆分为当月区域证据、字段月份证据、文件名证据，并定义冲突优先级。
3. 用标题行、表头行、相邻空白列/下一标题和连续数据行识别任意数量子表，生成稳定但不依赖源文件编号的内部键。
4. 页面直接使用解析结果中的子表名称与顺序生成切换按钮，缺少或新增子表均随当月文件变化。
5. 为旧版、新版、缺表、改名、错月文件补充上传和动态重解析回归。
6. 递增版本、更新说明并完成桌面/窄屏及真实文件上传验证。
7. 新增分公司“营收趋势分析”模块：把动态表头转换为可组合数据标签，管理员配置统计卡片，历史预计营收按月份形成可滑动趋势图。

## 验收标准

- 截图中的旧版营收统计文件不再误报 `2020-06`，可识别正确上传期间。
- 旧版缺少部分子表或子表改名时仍可上传；页面只展示文件实际存在且验证通过的子表。
- 新增子表无需修改固定 B/L 编号数组即可在对应模块显示。
- 每个子表列宽截止到最后一个已识别字段，右侧非本表内容不会混入。
- 错月或多月冲突仍给出明确证据并阻止错误归属。
- 完整测试、部署检查和真实浏览器验证通过。
- 分公司之间不存在数据串读；管理员组合口径保存后对所有公司和员工统一生效。

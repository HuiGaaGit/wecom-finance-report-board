# 17企微财务报表看板：企微与阿里云部署准备 ExecPlan

## 目标

把当前仅适合本机演示的 Node.js + SQLite 应用整理为可部署到阿里云 ECS、可从企业微信工作台安全进入的单实例生产候选版。此阶段交付部署代码、配置模板、检查脚本和操作手册；不在缺少域名、证书、企微 Secret、ECS 地址和运维账号时直接操作线上资源。

## 当前约束

- 本地演示通过 `x-demo-employee` 切换身份，生产环境必须忽略该请求头。
- 当前数据层为 SQLite 和本地上传目录，因此首个生产版本只支持单实例 ECS；横向扩容前再迁移 PostgreSQL/OSS。
- 财务数据和企微身份均为敏感信息，公网入口必须使用 HTTPS，应用进程只监听 `127.0.0.1` 并由 Nginx 反向代理。
- 企微 OAuth 回调需要已备案、可公网访问的 HTTPS 域名，以及应用的 CorpID、AgentID、Secret。
- 2026-08-27 已对候选 ECS `8.163.95.203` 完成只读体检：Alibaba Cloud Linux 3、Node.js 20、Nginx 1.24，约 30GB 可用，`3180` 空闲；该主机现有项目 14 等服务，项目 17 目录尚未创建，正式写入前仍需确认它就是目标主机。
- 2026-08-27 用户改用已完成备案的 `qiandianxiaoq.com` 作为正式入口；其 A 记录已解析到目标 ECS。该域名此前因没有独立 Nginx 虚拟主机而落入默认站点并显示项目 14 的账簿登录页，并非项目 14 的正式公网入口；项目 14 仍只允许通过 Tailscale 私网访问。当前仅启用了返回 503 的 ACME/企微校验临时站点，项目 17 完整代理配置仍只暂存，须在企微参数完成后再激活。
- 2026-08-27 用户确认项目 17 使用 `https://qiandianxiaoq.com/report/` 路径入口；应用、静态资源、API、登录跳转、会话 Cookie 和 OAuth 回调统一使用 `/report` 基础路径，Nginx 仅把该路径反向代理到回环端口 `3180`，其他路径不代理到项目 17。
- 企微自建应用已创建，服务器已写入应用公开配置；新应用 Secret、企业身份参数与首位管理员仍待通过服务器安全配置完成，不在聊天中传递。
- `qiandianxiaoq.com` 的 Let's Encrypt 证书已签发到 `/etc/letsencrypt/live/qiandianxiaoq.com/`，有效期至 2026-11-25；ECS 当前无法直接连接 Let's Encrypt ACME 地址，自动续期预计会失败，上线后必须修复出站链路或改用可自动续期的证书方案。

## 实施步骤

1. 增加 `AUTH_MODE=wecom`：实现企微 OAuth 跳转、回调换取 userid、员工资料同步、HMAC 会话 Cookie 和退出入口；`demo` 模式继续服务本地开发与自动化测试。
2. 生产模式禁止 `x-demo-employee` 和默认管理员回退；未登录页面跳转企微认证，API 返回带登录入口的 401。
3. 增加 `.env.production.example`、环境就绪检查和敏感配置校验。
4. 增加 Ubuntu / Alibaba Cloud Linux ECS 的 systemd 服务、Nginx HTTPS 反向代理、SQLite 每日备份 service/timer、发布和回滚脚本；初始化优先复用已有系统组件，仅缺少组件时才访问 `apt-get`/`dnf`，发布包用系统 Python 解压以避开额外 `unzip` 依赖，配置完成前不启动服务或激活 Nginx 模板。
5. 编写企微后台配置、阿里云安全组/域名/证书/目录权限、首位管理员授权、上线验收和回滚手册。
6. 升级版本并运行语法检查、部署就绪检查、自动化测试和本地浏览器冒烟验证。

# 顾问所属公司、营收状态与人事标签实施计划

## 目标

基于生产 `v1.1.54` 连续升级顾问投入产出比模块：把营收匹配状态拆为“已匹配、无营收、缺营收、缺工资”，把“业绩归属/地区”统一改为企业微信花名册提供的“所属公司”，为“新/离职”圆标提供不遮挡表格的日期提示，并统一表头、列宽、字号及管理员诊断权限。

## 数据与权限边界

- “缺营收”只表示集团当月营收统计表未发布，或已发布文件无法解析出当前期间的总营收明细表；“无营收”表示营收来源已就绪，但该顾问无明细或汇总为零。
- “无营收”不属于缺失来源，不进入来源待补齐提示；发布营收统计表后的既有自动刷新和人工刷新会重新判定。
- 所属公司不再回退营收统计表的业绩归属，只读取财务专用企业微信在线花名册。
- 花名册“在职/离职”仅精确读取 `D:F` 三列（所属公司、姓名、英文名）；离职日期另以 `B:B` 单列读取并按行配对。每个响应都校验起始列、最大有效宽度和表头，任一异常即丢弃本次结果且不覆盖旧快照。
- 脱敏快照只允许姓名、英文名、所属公司、在职/离职状态和离职日期。普通员工接口不返回匹配状态、规范姓名或来源诊断明细；匹配状态列及其筛选排序仅管理员可见。
- 保留财务专用企业微信 CLI、独立凭证、授权检测和 systemd 监听，不读取整表，不接触小W、小Q或其他项目。

## 实施步骤

1. 扩展受控花名册同步器与快照解析，增加所属公司和离职日期，并兼容切换期间的旧版安全快照。
2. 后端按营收来源是否可解析区分缺营收和无营收，按管理员权限裁剪诊断字段；公司汇总改为所属公司口径。
3. 前端统一所属公司命名、公司筛选/汇总、管理员状态筛选，并将新/离职标记改为同尺寸可交互圆标。
4. 日期提示使用固定定位浮层锚定标记，自动上下翻转并限制在视口内；支持悬停、键盘聚焦、触屏点击、Escape 和点击外部关闭。
5. 重排表头与列宽，统一文字、排序和漏斗按钮间距；桌面尽量铺满，平板和手机只允许表格容器横向滚动。
6. 补充同步范围、接口裁剪、状态口径、前端计算和响应式样式回归，完成桌面 1280/1440、平板和 390×844 浏览器验收。
7. 递增补丁版本，固定候选包；由统一部署任务完成备份、服务器 Docker 全测、受控切换、企微同步冒烟和生产页面验收。

## 验收标准

- 管理员能看到并筛选四种匹配状态，普通员工 API 和页面均无匹配状态字段及列。
- 营收来源已就绪但个人营收为零时显示“无营收”，且页面不提示缺营收数据源。
- 所属公司来自企微花名册，缺失明确显示“待补充”；公司汇总不再出现地区/业绩归属措辞。
- “新/离职”圆标尺寸一致，鼠标、键盘和触屏均可查看相应日期，提示不遮挡入职日期列且不越出视口。
- 1280、1440 桌面无整页横向滚动；平板和 390px 手机仅表格容器内部可横向滚动，侧栏不被压缩。
- 提成默认未选、报销科目下拉、管理员隐藏名单和导出按钮移除全部保持。

## 风险与回滚

- 新版本部署后必须先手工执行一次财务专用目录同步；如果 D:F 或 B:B 范围、表头、授权或快照字段校验失败，立即停止上线并保持 `v1.1.54`。
- 本轮不做数据库结构迁移；回滚恢复上一镜像、源码和原 systemd 文件即可，数据库完整时不得覆盖现有业务数据。
- 发布前后核对数据库完整性、上传/快照/明细计数、财务企微授权状态、三个监听状态和五个 unit 哈希。

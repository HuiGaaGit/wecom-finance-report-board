# 集团营收统计表模块实施计划

## 目标

在“桉侨集团”查看范围下新增“营收统计表”模块，以用户提供的 `2026年营收统计表26.7.xlsx` 为首个事实源。左侧父模块展开三个一级维度，页面内再切换各维度对应的二级统计表：

- 集团维度：B1 营收总表、B2 项目营收排行、B3 项目经理营收明细。
- 单独直客维度：B4 直客项目来源统计总表、B5 直客营收排名、B6 直客营收明细排名统计。
- 单独渠道维度：B7 渠道营收排名、B8 渠道营收明细排名统计。

## 数据契约

- 识别工作表名 `2026年数据统计汇总表（mia）` 及同结构的其他年度文件。
- 以第一行三个“维度统计”标题和第二行 `B1` 至 `B8` 标题定位表块，不依赖固定月份或固定数据行数。
- 每个表块从第三行读取表头，从第四行起读取至首个空白分隔区；保留数值类型、占比和项目数量精度。
- 作为独立 `revenue_statistics` 报表类型保存上传批次、解析结果、版本和发布状态，只允许归属“桉侨集团”。
- 页面只读取同集团、同期间的当前发布版本；原始 Excel 始终保留，旧批次不覆盖。

## 实施步骤

1. 后端增加报表类型、权限节点、既有角色/员工权限迁移和集团范围限制。
2. 扩展 Excel 解析器，输出三个一级维度和八张二级表的结构化 JSON。
3. 上传页增加“集团营收统计表”文件入口，并支持文件名自动识别、预览、发布、撤回与历史版本。
4. 左侧导航为“营收统计表”增加三个下拉子模块；页面内用二级页签切换 B1-B8。
5. 新页面增加响应式宽表、金额/占比/数量格式、来源信息、口径提示和员工水印。
6. 补充后端接口、权限、解析、导航和前端静态回归测试；使用用户文件完成本地上传发布与浏览器验证。
7. 同步版本与 README，构建版本化发布包并按既有阿里云发布链部署，验证健康检查和备份。

## 验证标准

- 集团范围显示营收统计表，单家公司范围不显示。
- 三级交互完整：营收统计表父模块 → 三个维度 → 对应二级表。
- 用户文件识别为一个 `revenue_statistics` 批次，八张表均存在且 B1 总营收与源表一致。
- 无权限员工无法看到模块或访问原始数据接口。
- 桌面和手机均无整页横向溢出，宽表仅在模块内横向滚动。
- `node --check app.mjs`、`node --check public/app.js`、`npm test`、`npm run check:deploy` 全部通过。

## 决策记录

- “3 个数据维度”按源表月度 B1-B8 区域实现，不把年度 L1-L6 混入本模块。
- 三个维度彼此独立展示；直客与渠道不做相加汇总，并在页面保留源表口径提示。
- 营收统计表只提供汇总浏览/导出权限，不开放科目明细下钻权限。
- 原始 Excel 是唯一事实源；解析不固化 2026 年 7 月数据，后续同结构月份沿用同一导入流程。

# 17 企微财务报表看板：资产负债分析卡片

## 目标

在资产负债表页面右上方增加“资产负债分析”入口。点击后以弹窗展示当前公司、当前月份、当前已发布版本中的资金来源、资金去向、关键指标卡片和易读图表。发布新版本后不沿用旧缓存，分析结果自动切换到新发布批次。

## 数据契约

- 数据只取所选公司与期间“当前已发布”的资产负债表原始上传 JSON，不另建人工维护副本。
- 从工作表完整有效区域识别“钱的来源”和“钱的去向/钱的去处”两张分析表；识别依据是标题、`项目`、`金额` 三层锚点，不依赖固定单元格坐标。
- 每行保留源表原始名称、原始行列位置和金额，同时映射为稳定分类键；未识别的新项目仍以 `other` 保留，不静默丢弃。
- 分别保存源表声明合计、逐项计算合计，并计算来源与去向差额。只有两侧声明合计存在且差额不超过 0.01 元时标记为勾稽一致。
- 接口每次按当前发布批次即时解析并返回映射版本、上传批次和发布时间。前端打开弹窗、手动刷新以及弹窗保持打开期间都会重新请求；响应禁止浏览器缓存。

## 交互与视觉

- 入口与“上传新报表”位于资产负债表抬头右上方的操作区，使用带图标的次级强调按钮，避免挤压报表标题。
- 弹窗顶部展示公司、期间、发布版本/批次和刷新状态；支持关闭按钮、遮罩点击、Esc 关闭与焦点恢复。
- 关键卡片展示资金规模、来源项目数、去向项目数、勾稽差额。
- 使用二维环形图、排序图例和金额/占比替代源表 3D 饼图，移动端切换为单列；数值和图例始终可读，不只依赖颜色表达。
- 没有分析区、分析区不完整或新版本发布时给出明确状态，不把旧版本数据冒充为当前数据。

## 回滚与安全

- 不修改 SQLite 业务表结构；分析数据始终可由上传原件重算。
- 部署前执行 SQLite 一致性备份，并保持上传目录挂载不变。
- 生产回滚只切换上一版本镜像，不覆盖数据库或上传原件。
- 只使用 `deploy/ssh_config` 的项目 17 专属主机别名，不把该登录配置用于其他项目。

# 顾问人事状态与通讯录字段

## 目标

在顾问投入产出明细中增加入职日期、英文名和离职状态，并在相关报表发布后自动刷新企微匹配；读取失败时在界面给出授权、文档权限、字段范围或数据准备指引，同时避免财务服务保存或暴露花名册中的身份证号等无关敏感字段。

## 数据口径

- 入职日期：继续以所选期间已发布“每月工资表”的“入职日期/入职时间”字段为事实源。
- 离职状态：由受控同步任务仅读取企业微信在线表格“花名册”的“离职”工作表姓名列；命中当期工资顾问时显示红色圆形“离职”标识。
- 英文名：企业微信通讯录 alias 为主；花名册同名人员的英文名仅作缺失兜底。重名或匹配不唯一时留空，不猜测。
- 同步快照只允许姓名、英文名、任职状态、同步时间和来源摘要，不包含身份证号、手机号、工资金额或其他人事字段。

## 实施

1. 为财务服务增加只读、限大小、限字段的顾问目录快照读取器，并把快照修订时间纳入顾问分析版本签名。
2. 合并工资顾问与目录快照，返回 `englishName`、`isResigned`；入职日期仍完全来自工资表。
3. 调整顾问表格、筛选、排序和 CSV：列顺序为“顾问、入职日期、英文名、业绩归属……”，姓名旁支持“新”和红色“离职”标识。
4. 提供宿主机最小权限同步脚本：读取花名册允许列、查询企业微信通讯录 alias、生成脱敏快照；财务容器不持有企业微信凭据。
5. 更新部署示例、运行文档、自动化回归、版本和发布包。
6. 工资表或营收统计表发布成功后，财务应用只向数据卷写入不含人员与文件名的刷新请求；宿主机 `systemd.path` 即时启动同步器，小时级 timer 继续兜底。
7. 同步器以脱敏状态文件返回成功、执行中、授权失效、来源范围异常、文档/通讯录权限不足或缺少工资顾问数据；页面轮询状态并自动弹出相应处理指引。

## 验证

- 后端测试覆盖工资入职日期、英文名合并、离职标识、目录缺失/异常/超限及源版本刷新。
- 自动化测试覆盖单笔/批量发布触发、刷新请求最小字段、手动刷新权限、同步状态与前端指引。
- 前端测试覆盖列顺序、筛选排序导出、双状态标识和无横向溢出保护。
- 运行 `node --check`、`npm test`、`npm run check`、`npm run check:deploy`、`git diff --check`。
- 以桌面和手机视口验收表格、筛选按钮、状态标识和控制台。

## 部署与回滚

- 同步器需要在生产宿主机完成一次企业微信 CLI 授权后由路径触发器和定时任务运行；只写入财务数据目录中的脱敏快照与状态，权限为目录 `0700`、文件 `0600`。
- 发布前备份现有数据目录；本次不修改 SQLite 结构。回滚旧镜像时可保留快照，旧版本不会读取；也可停用同步定时任务。
- 不自行部署生产，由统一部署任务执行备份、构建、同步授权与公网验收。

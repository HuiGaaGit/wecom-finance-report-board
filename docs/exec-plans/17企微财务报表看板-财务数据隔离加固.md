# 财务数据隔离加固 ExecPlan

## 目标

在 `1.1.22` 隔离候选上完成 `1.1.23` 同源路径安全加固，使同服务器正常运行的小Q及其他普通业务容器无法读取财务数据库、上传原件、解析结果、备份和环境密钥，也无法通过共享卷、Docker 网络、Docker Socket、服务端公开路径、代理日志或缓存获取财务正文。正式入口继续使用 `https://anqiaoyiminxq.com/platform/finance/`，不新增域名、DNS 或证书。小Q只保留身份提供方职责，不接收任何财务正文。

同一 Origin 下，小Q页面脚本与财务页面对浏览器而言没有安全边界：`Origin`、`Sec-Fetch-Site`、Cookie Path、CSP 均无法区分两者，根作用域 Service Worker 也可能拦截财务路径。因此本计划交付服务器、容器、文件、日志与接口强隔离，但不宣称消除了同源前端脚本、XSS、根作用域 Service Worker、宿主机 `root`、Docker daemon 或内核失陷风险。若需覆盖浏览器同源风险，必须使用独立 Origin 或独立服务器。

## 交付范围

- 财务容器使用专用固定 UID/GID，数据目录采用最小权限并在应用启动时使用 `umask 077`。
- 部署检查拒绝其他容器挂载财务数据目录或 Docker Socket，核对财务网络成员、端口监听、容器用户及数据目录 owner/mode。
- 财务后台仅允许通过固定 GET 白名单访问小Q身份接口，不向平台发送请求正文。
- 财务接口增加无缓存、安全响应头和许可 Origin 校验；不启用宽泛 CORS。
- 财务正式页面继续使用 `/platform/finance/`；Nginx 对该路径关闭访问日志、请求/响应缓冲、代理缓存和临时文件，并拒绝回环、同机公网地址及 RFC1918/ULA 服务端来源。
- 财务页面只在交换 15 分钟 HttpOnly 财务会话时读取小Q现有短期 access token，不读取、刷新或复制 refresh token，也不写入财务自有持久存储。
- 保留 CSP、防嵌入、no-store、同源资源策略、COOP、no-referrer 与 `worker-src 'none'`；明确这些响应头不能隔离同 Origin 的小Q脚本或根作用域 Service Worker。
- 更新安全回归、生产运维、发布与回滚说明，生成 `1.1.23` 候选包和 SHA256；本任务不自行部署。

## 兼容约束

- 保留 `1.1.20` 管理员浏览日志、`1.1.21` 权限中心“全部不可见”及此前所有业务功能。
- 不读取或输出生产 Secret，不修改小Q业务数据，不将财务数据导入小Q数据库、知识库、日志或对象存储。
- 生产继续复用现有 `anqiaoyiminxq.com` HTTPS 证书，不创建 `finance.anqiaoyiminxq.com` DNS 或证书；统一部署任务负责生产备份、UID/GID 迁移和最终验收。
- 数据目录权限迁移只能作用于精确路径 `/data/data/wecom-finance-report-board`，禁止对宽泛目录递归变更。

## 验收标准

- `node --check app.mjs`、`node --check public/app.js`、`npm test`、`npm run check`、`npm run check:deploy`、`git diff --check` 全部通过。
- 财务 API 对非许可 `Origin` 请求返回拒绝，对许可 Origin 正常工作，所有敏感接口响应不可缓存。
- CSP、`nosniff`、`no-referrer`、防嵌入、同源资源策略和权限策略存在且不破坏现有页面。
- 平台请求仅出现 `/auth/me`、`/data-dist/my-roles`、`/data-dist/user-groups` 三个 GET 路径，且没有财务正文或请求 body。
- 财务页面只读取小Q `localStorage` 中的 access token，不调用 `setItem`，不读取或刷新 refresh token；财务会话 Cookie 为 HttpOnly、Secure、SameSite=Strict 且 Path 固定为 `/platform/finance`。
- Compose 使用专用 UID/GID、只读根文件系统、最小 capabilities、独立网络和回环端口；隔离检查能对错误挂载、Docker Socket、网络成员和权限设置失败退出。
- Nginx 同源财务路径拒绝回环、同机公网及私网服务端来源，上传正文不进入代理缓存、缓冲临时文件或访问日志。
- 文档和测试明确记录同 Origin 前端脚本与根作用域 Service Worker 的剩余风险，不把路径隔离描述为浏览器安全边界。

- 继续使用现有 `/platform/finance/`，不创建独立域名或登录桥接；Nginx 切换前先执行语法测试并保存当前配置。
- 回滚恢复旧 Compose、Nginx 和镜像；数据目录 owner/mode 仅在旧镜像确实需要时恢复。数据库结构无回退需求时不得覆盖业务数据。
- 同源路径方案只能报告服务器、容器、文件、日志和接口隔离已完成，不得宣称浏览器同源风险已消除。

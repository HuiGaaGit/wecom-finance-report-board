# 桉侨集团财务报表看板

版本：`1.1.63`
生产环境继续使用 `https://anqiaoyiminxq.com/platform/finance/`，复用桉侨小Q现有企微登录但不接收财务正文。财务页面只在建立会话时读取小Q现有短期 access token，不读取或刷新 refresh token；财务服务动态校验 `admin`、`general_manager`、`finance` 三个组并换取 15 分钟、Path 限定为 `/platform/finance` 的 HttpOnly 会话。旧财务自建应用和独立企微 OAuth 已停用，财务模块不连接 AQLLM 数据库或数据卷。

同域名路径可以实现文件、容器、网络、日志和接口的强隔离，但不是浏览器安全边界：小Q页面脚本与财务页面具有相同 Origin，根作用域 Service Worker 也可能覆盖财务路径。若需要阻止同源前端脚本、XSS 或 Service Worker 读取财务响应，必须使用独立 Origin 或独立服务器。

企业微信工作台 H5 财务报表展示首版。当前包含本地演示身份切换、八类财务报表的独立授权、公司与期间范围、历史版本、图表、原始资料上传和权限管理纵向切片。

## 当前首版能力

- 广州新版序时账按真实表头动态识别“借方金额/借方本币”“贷方金额/贷方本币”、客户、项目和备注列；主营业务、费用分析、财务费用支付方式、序时账页面及报表下钻统一复用该映射。源表未提供项目列时不会把部门名称误作项目，同凭证只有一个合同号时允许缺号成本分录继承；货币资金等资产负债表汇总项目可映射到银行存款、库存现金等明细科目。
- 财务资料与同服务器小Q采用三层隔离：专用 `20117:20117` 容器用户和 `0700/0600` 数据权限；独立 Docker 网络、回环端口、无 Docker Socket/共享卷检查；同源财务路径严格 CSP/来源校验/无缓存，并在 Nginx 拒绝回环、同机公网和私网服务端来源，同时关闭访问日志、请求/响应缓冲和代理缓存。财务后台访问小Q时仅允许三个固定身份接口的无正文 GET 请求。每月工资表被固定为内部敏感数据源，不授予任何角色通用报表范围，也不提供 raw、summary、detail、versions 或 export 整表接口。
- SQLite 一致性备份和异机备份状态文件统一按 `0600` 创建，与运行时隔离检查保持一致；定时备份完成后不会再使生产隔离验收失效。
- 管理员侧栏新增“浏览日志”：统一记录全体员工的页面浏览、报表与分析数据访问以及上传、发布、授权等操作；可按人员、浏览/操作类型、动作、模块、公司、期间、起止日期和关键词组合筛选，支持分页、展开详情、全选与勾选批量删除。普通员工不显示入口且管理接口拒绝访问，删除日志的动作自身继续留痕。
- 桉侨集团范围提供财务人员专用“各公司往来校验”：按同期间所有已登记经营公司的已发布科目余额表动态生成唯一双边组合及 N×N 矩阵；新增公司会自动进入资料完整性检查、组合计算和矩阵，不再依赖固定七家公司，缺少报表时明确标记“资料缺失”。页面取消重复的六项概览卡，以应收账款、其他应收款减应付账款、其他应付款计算净往来，主账、调整和广宣费/投流推广分别列示；矩阵和异常表识别主体待映射、单边挂账、方向冲突、金额差异及余额方向异常，默认仅看异常。点击组合可查看双方科目余额，拥有独立明细权限时继续读取双方序时账且排除结转分录；未授权公司和期间由后端过滤，特殊名称不会自动算作一致。

- “待处理发布”在发布或删除完成后强制以无缓存请求重新读取当前筛选结果，并用请求序号丢弃较慢的旧响应；操作进行中会锁定同页发布/删除按钮，防止重复提交。页面版本与后台运行版本不一致时会停止数据操作并明确要求重启服务，避免新前端连接旧后台后继续展示已处理记录。
- 上传成功后自动切换到“待处理发布”，并把上传记录筛选同步到本次实际写入的公司和月份；上传校验自动纠正地区或期间时，新生成的已校验批次也会立即显示，不再被进入页面时的旧筛选条件隐藏。
- 历史资料导入兼容早期集团合并文件把主表命名为“利润表”和早期工资文件使用 `Sheet1` 等通用名称；集团文件只有主表时明确标记为无公司分表可勾稽，有公司分表时仍强制逐行加总一致。汇总文件中的序时账和科目余额表会核对实际期间，错月子表不生成批次并在上传结果中说明，不影响同文件内期间正确的其他报表。

- 顾问投入产出明细支持“基本工资、提成、报销费用、投流消耗费用”四类投入口径；基本工资、报销费用和投流消耗费用默认计入，提成默认不计入。只有管理员可以调整投入项目，并通过报销费用旁的紧凑漏斗打开 WPS 风格科目面板，搜索、全选、清空或逐项选择当期已有二级科目；取消不保存，明确点击“保存并应用”后按期间写入服务端并对全员生效。普通员工只看到当前统一口径，不接收候选科目、金额笔数或配置组件。关闭投入项目时对应表格列与筛选项同步隐藏；明细表不展示来源列或导出按钮，桌面端全部列紧凑铺满模块，窄屏只允许表格容器横向滑动。
- 顾问模块新增管理员专属“名单显示设置”：管理员可按姓名搜索并取消勾选不应展示的顾问，设置在服务端全局保存，隐藏人员会同时从明细、指标汇总、平均投入产出比和地区统计中剔除；普通用户不接收隐藏名单和设置入口。当前页面暂不展示导出按钮，投入标签与名单/筛选操作分组排列。
- 顾问投入产出明细的“投流消耗费用”列位于“报销费用”右侧；数据只读取每月集团上传“顾问消耗-营收表”的“汇总”工作表，通过合并表头或明确字段动态定位顾问英文名和“总消耗/元”。英文名匹配忽略大小写、空格与常见标点，只有唯一匹配才计入顾问；市场部渠道行、汇总行、重名和未匹配记录不猜配，并在来源区列示未匹配行数及金额。该原表与工资表同为分析专用敏感数据源，不开放通用整表浏览、版本或导出接口。
- 顾问明细前四列固定为顾问、企业微信英文名、工资表入职日期和所属公司；所属公司只取花名册，不再回退使用营收统计表“业绩归属”，缺失时显示“待补充”。当月入职显示青色圆形“新”，离职人员显示同尺寸红色圆形“离职”；悬停、键盘聚焦或触屏点击标签分别显示入职日期和离职日期，提示自动避让视口。匹配状态拆分为“已匹配、无营收、缺营收、缺工资”，其中“无营收”表示营收表已发布且该顾问当月营收为零，不计入来源缺失；该诊断列及筛选仅管理员可见，普通员工接口不下发匹配诊断字段。
- 财务应用从已发布工资表生成 `consultant-directory-input.json` 最小顾问匹配清单，内容仅含顾问姓名；宿主机同步器不打开 SQLite、不加载宿主机原生模块，也不引用其他项目目录。同步器通过财务专用企业微信 CLI 1.2.0 对“在职”“离职”工作表分别精确读取 D:F 的所属公司、姓名、英文名，并仅对“离职”工作表额外读取 B:B 的离职日期；B 与 D:F 按原行号合并，不读取 C 列离职原因或其他字段。任一响应起始列、有效宽度、表头或行对齐异常时丢弃整次结果并有限重试，连续 3 次异常立即停止且不覆盖旧快照，不提供扩大读取范围的旁路开关。
- 每月工资表或营收统计表发布成功后，系统自动写入不含人员、文件名和财务金额的刷新请求，由宿主机 `systemd.path` 立即重新读取企微花名册和通讯录，小时级定时器继续兜底。同步状态会回传顾问模块；授权失效、文档/通讯录无权限、花名册重名/缺表、字段范围异常或缺少已发布顾问工资数据时，页面自动弹出对应处理步骤，并支持“重新匹配”后每 3 秒检查进度。
- 财务专用同步器每小时执行一次 `auth show --status`，因此约 7 天的独立授权失效后会自动触发重新授权服务。服务只把经过域名、路径、来源参数、临时码格式和有效期校验的企业微信临时链接返回给权限管理员；普通顾问用户只看到联系管理员的提示。管理员在看板内点击链接并确认后，授权服务自动复检并提交一次顾问目录刷新，不复用小W凭据，也不把令牌、Cookie、二维码或企微命令输出写入看板数据。
- 顾问投入产出模块顶部提供可点击的“顾问平均投入产出比”卡片，按管理员已保存的统一投入口径计算所有有投入顾问个人比率的算术平均；弹层按企业微信花名册所属公司展示各公司的投入、预计营收和投入产出比。

- 桉侨集团范围新增“顾问投入产出比”：工资表以“部门名称含顾问”形成顾问主名册，非顾问部门人员不进入明细；投入读取顾问当月基本工资、提成及各授权公司序时账中明确归属于顾问的销售/管理费用，排除工资提成和结转重复。产出只读取营收统计文件“总营收明细表”中与所选期间一致的月份、签约顾问和预计营收，并且仅归入工资顾问名册，避免渠道或其他人员混入；营收表的业绩归属不再作为顾问所属公司来源。
- 每月工资表会按上传时选择的会计期间定位对应工资工作表，兼容 `202607工资表`、`2026年7月工资表`、`26年7月工资表` 等命名；“部门”现为必需字段，姓名支持“中文姓名/姓名”，基本工资优先读取精确“基本工资”字段，提成优先读取“本月提成”且不混入“往期提成”，同时识别“入职日期/入职时间”等字段。当月入职顾问在姓名旁显示“新”标记，点击可查看标准化入职日期。文件仅含其他月份工资页时会明确拦截，不再误取第一个历史月份。
- 顾问投入产出页面提供“重新匹配”按钮，停留页面时每 60 秒检查一次工资、营收统计表及各公司序时账的最新发布版本，匹配请求执行期间改为每 3 秒检查；浏览器标签恢复可见时立即检查，数据源版本签名变化后自动重绘。旧发布批次若缺少新版营收明细结构或工资入职日期字段，会从保留的原始上传文件一次性重新解析并缓存，不要求重新上传。

- 左侧“资产负债表”前新增“财务数据简报”：按当前公司与期间自动从已发布的资产负债表、利润表、集团合并利润表及营收利润口径文件联合取数，生成月度收支文字；预计营收可用地区简称稳定匹配合并文件中的完整主体名称，并兼容千分位及带“元”的金额文本；营业收入、营业成本、销售费用、管理费用和财务费用直接取利润表总数，广宣费保持单独归集展示；集团口径自动汇总各公司账户余额与广宣费，来源不齐时明确显示缺失项且不按零处理。
- 财务数据简报进入页面时立即读取最新已发布数据，页面停留期间每 60 秒自动刷新，浏览器标签恢复可见时立即补刷新，并提供与公司、期间筛选控件保持同一水平行的人工“刷新数据”按钮；自动刷新状态仅保留无障碍提示，不再在按钮下方显示更新时间说明，刷新失败时保留上一版内容并自动重试。广宣费仅读取相应月份科目余额表末级相关科目的“本期发生额—借方”，不抵减贷方且不回退序时账；金额直接列示在销售费用原文字说明中，不再显示额外来源明细。
- 财务数据简报卡片提供“一键复制纯文字”，复制标题、公司口径、一级项目及其二级说明；全部项目连续逐行输出且不插入空行，可直接粘贴到企微或文档。
- 管理员和财务负责人默认拥有“编辑二级说明”权限，其他员工可在权限中心单独授权；二级说明按公司、会计期间和一级项目独立保存，支持自由文字的新增、编辑、删除并记录操作日志。添加入口平时隐藏为一级项目左侧的浮动 `+`，悬停或键盘聚焦时出现，位置比同行项目名称低约半个字符以表示向下插入；点击后只展开一个横向自由文字框，不再强制拆分项目名称和金额。已保存说明比一级项目小一号；只读人员可查看但不显示编辑入口。“营收综合利润”固定为最终一级结果，不支持二级说明。
- 资产负债表右上方提供“资产负债分析”入口：按当前公司、期间和当前已发布批次即时识别源表中的“钱的来源”“钱的去向/去处”项目及合计；弹窗左侧用页签滑动切换两张原序项目/金额表，右侧同步切换大幅二维环形图，不再并列两张表或显示冗余说明。左右区域等高分配，表格、金额与图表直标字号已放大；每个正数色块都以防碰撞引导线直接标注项目和比例。点击表格、色块或标签时，对应色块动态放大、其余项目弱化，并在圆心展示占比和金额；SVG 原生黑色焦点框已由柔和高亮替代，同时保留键盘操作。无金额项目保留原表短横线但不可误选；弹窗每 60 秒检查发布版本，切换到新报表时重算且保留当前来源/去向页签。
- 现金流量表右上方提供统一样式的“现金收支分析”入口：只读取当前公司、期间和当前已发布现金流量表中的“累计现金收支明细”，按标题以及“增减项、项目、金额”表头动态定位，不依赖固定行列。“期初/加/增加/流入”映射为钱的来源，“减/减少/流出”映射为钱的去向；不同月份新增项目保持源表名称和顺序，金额兼容千分位、元、括号负数和短横线。弹窗沿用左侧页签表格、右侧直接标注环形图以及表格/色块/标签三方联动，手动刷新、每 60 秒和页面恢复可见时都会按当前发布批次重算。
- 首页点击“开始浏览报表”后，按当前员工可见的财务模块顺序进入第一个模块；默认优先进入“财务数据简报”，无简报权限时回退到首个可见财务报表，不会误跳到上传、分析或管理模块。
- 旧数据库升级时会一次性消除模块排序并列值并把“财务数据简报”归位到“资产负债表”之前；之后管理员保存的完整全局模块顺序继续持久化，刷新和重新登录后保持一致。
- 资产负债表、利润表、桉侨集团合并利润表、（营收利润口径）合并利润表、营收统计表、现金流量表、科目余额表和序时账。
- “桉侨集团”作为独立查看范围；集团范围显示“桉侨集团合并利润表”和“集团合并利润趋势图”，公司范围不混入集团报表或集团分析。左侧合并利润表父模块可展开同一集团文件内的各子公司完整名称，点击子项直接查看对应工作表，金额不跳转序时账；合并利润表自动提取正式正文 B1:E36，并校验集团金额与公司分表逐行加总一致，报价单和毛利辅助区不进入报表模块。
- 集团范围的“营收统计表”父模块在左侧展开集团维度、单独直客维度、单独渠道维度和营收统计累计数据四个子模块；前三项分别切换 B1-B3、B4-B6、B7-B8 当期统计表，第四项独立提供年份选择及 L1、L2、L2-1、L3、L4、L5、L6 七张年度累计子表。累计子表按钮把括号内口径换行居中并按内容收紧宽度；数据按分区标题、子表标题和连续字段表头动态定位实际列宽，允许历史月份缺少部分累计子表，且不会把右侧非累计业务区吸收到最后一张累计表。已发布旧文件会按解析器版本从保留的原始 Excel 自动补解析，无需重新上传。

- 主营业务分析按序时账展示本期项目收入成本明细、项目数量环比和本年毛利月度趋势；项目数量对比表头、说明和图例会根据当前选择期间显示实际月份，例如选择 `2026-07` 时显示“7月”和“6月”。管理员及已获当前公司、期间序时账明细权限的人员可点击确认收入或确认成本金额，在弹层查看真正构成该数字的源分录行；接口不会向未授权人员下发分录，且结转分录不纳入展示。趋势图仅保留毛利主线并按毛利自身区间突出态势，非零月份直接标注毛利金额；项目数量采用表格内嵌双条形对比，收入取主营业务收入贷方，成本取主营业务成本借方。项目名称和客户名称均按序时账表头动态定位；客户列为空时可从带订单号的收入摘要识别客户，同一日期、同一凭证只有一个订单号时，摘要漏写订单号的成本行会继承该订单及客户，多订单凭证保持未识别以避免错配；不同模板中的“会计001、会计002”等制单人或审核人编号不会被误识别为业务项目。
- 主营业务分析会读取最新已发布的集团报单表，按规范化合同编号精确匹配并优先采用报单表客户名称和项目名称；收入、成本和毛利金额仍只取当前公司序时账。页面同时展示报单表合同总数及本期合同命中数，未命中合同保留序时账识别结果并提示，不进行客户或项目名称模糊匹配。
- 费用分析按序时账展示销售费用、管理费用二级科目本期/上期及变动率，配套年度月度趋势和本期占比；财务费用按摘要识别银行转账、通联扫码、富友、财付通并匹配手续费和手续费比率。
- 生产权限管理页由小Q管理员同步管理员、总经理和财务组三个成员组，支持按姓名或成员组搜索、查看同步人数与状态，并可手动刷新。
- 权限管理员可直接拖动左侧导航中的六点手柄调整全局看板模块顺序；无论从哪家公司进行调整，保存后所有公司和所有员工都会继承同一全局相对顺序，再按各自报表权限过滤不可见模块。权限管理页不再保留重复的模块排序区域。
- 默认导航顺序将“上传报表”放在“权限管理”正上方；既有环境只迁移一次，迁移后管理员仍可继续拖动调整并全员生效。
- 管理员可直接拖动资产净额分析、主营业务分析、费用分析和集团合并利润趋势图中的指标卡、表格及图表板块；拖动手柄采用独立绝对定位覆盖层，不参与模块宽度、网格轨道或内容排版，悬浮时显现，数据来源固定不参与拖动；换位采用 FLIP 动画，被挤开的板块平滑让位并轻微回弹；四个页面分别保存全局布局，普通员工只读取布局且不显示拖动手柄。
- 四个分析页面的每个子模块均提供独立折叠/展开按钮；折叠状态按当前员工和分析页面保存在本机，切换页面或刷新后继续保持，且不会影响管理员拖动排序。
- 首页固定在侧栏首位且不参与权限或拖动排序；其余模块按当前员工、公司和期间的权限过滤，未授权报表不会展示。
- 支持 `demo` 与 `platform` 两种身份模式：本地继续使用演示员工切换，生产环境复用小Q企微登录并忽略演示身份请求头；首次进入的授权员工默认没有财务数据权限，由财务权限管理员后续配置。
- 正式环境使用独立 Docker Compose、独立网络和 SQLite 持久目录，由主站 Nginx 反向代理。
- 正式地址为 `https://anqiaoyiminxq.com/platform/finance/`；静态资源、财务 API 和短期会话 Cookie 均限定在 `/platform/finance` 下。
- 页面持续展示ICP备案号“粤ICP备2022138475号-5”并链接工信部备案查询平台；桌面端位于侧栏底部，手机端位于页面底部。
- 顶部仅保留当前员工姓名和企微真实部门名称，不再展示认证状态或角色徽标；管理员可全局开启员工水印，在五张财务报表和序时账明细页重复显示员工、部门、公司及期间，水印不阻挡表格操作且不写入上传数据或导出文件。
- 顶部右上角提供轻量分享箭头，只复制不含登录凭证的正式地址供用户粘贴到企微聊天；接收人打开后仍需通过小Q企微登录，并按自己的成员组和财务数据权限显示。
- 报表底部的明细跳转提示与当前员工的明细权限联动；没有查看明细权限时不显示提示，金额也不呈现为可点击入口。

## 异机备份

新生产服务器每天北京时间 `00:15、08:15、16:15` 先生成 SQLite 一致性快照，再通过 SSH/rsync 把数据库备份、上传原件和恢复配置增量推送到旧服务器专用目录。旧服务器不运行当前项目，只作为隔离备份节点；同步不使用 `--delete`，上传原件长期保留，数据库与配置快照保留 90 天。实施、验证和恢复说明见 `docs/PRODUCTION_OPERATIONS.md` 与 `docs/exec-plans/17企微财务报表看板-新旧服务器异机备份.md`。
